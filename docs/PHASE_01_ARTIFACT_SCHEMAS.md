# Phase 1 artifact schemas

All Phase 1 research artifacts are UTF-8, canonically ordered, and generated by
`scripts/prepare_phase01_data.py`. CSV files use a header, LF line endings, JSON arrays in compact
canonical form, and empty CSV fields only where the schema explicitly permits a missing value.
Raw releases and the extracted corpus are intentionally ignored by Git; the manifests below are
explicitly trackable under `artifacts/data/`.

## Frozen TechQA artifacts

`techqa_split_assignments.csv` has one row per question and the exact contract columns:

`schema_version, dataset_revision, question_id, provenance_partition, question_sha256,
normalized_question_sha256, is_impossible, reference_status, gold_doc_ids_json,
gold_evidence_analysis_status, split_group_id, split, split_seed, split_algorithm_version,
component_manifest_sha256, split_frozen_at`

`techqa_split_components.csv` has one row per connected component:

`schema_version, dataset_revision, split_group_id, component_size, member_question_ids_json,
shared_gold_filenames_json, normalized_question_hashes_json, answerable_count, impossible_count,
assigned_split, split_seed, split_algorithm_version, component_sha256`

`techqa_corpus_manifest.csv` has one row per archive document:

`schema_version, dataset_revision, corpus_archive_sha256, doc_id, archive_path, filename,
raw_sha256, normalized_sha256, raw_bytes, normalized_chars, encoding, cleaning_version,
removed_payload_count, status`

`phase01_split_config.json` records the seed, ratios, grouping/normalization/optimizer versions,
solver status and objectives, achieved counts, component-manifest hash, freeze timestamp, and the
semantic split hash. `techqa_split.sha256` contains that semantic SHA-256 over the canonical
`question_id/split_group_id/split` mapping. It deliberately excludes timestamps.

## RAGTruth artifact

`ragtruth_manifest.csv` has one row per released response:

`schema_version, dataset_revision, response_id, source_id, official_split, task_type, source_name,
model, temperature, quality, response_sha256, prompt_sha256, source_info_sha256, label_count,
has_unsupported_span, implicit_true_count, due_to_null_count, label_types_json,
primary_grounding_eligible`

The manifest retains every task and quality state. `primary_grounding_eligible` is metadata for the
later frozen QA/good-quality analysis; Phase 1 does not train or evaluate a detector.

## Exceptional-reference artifact

`manual_evidence_alignments.csv` has:

`schema_version, question_id, status, manually_aligned_document, evidence_start, evidence_end,
annotator, rationale, timestamp, provenance`

For `DEV_Q014` and `DEV_Q094`, Phase 1 stores `status=unresolved` and null document/span/annotator
fields. This implements the frozen Phase 1 boundary: the anomaly is explicit, no evidence is
fabricated, and later gold-evidence analyses must exclude the rows until governed manual alignment.

## Metadata and validation

`dataset_metadata.json` records immutable source URLs/revisions/hashes, observed schemas and counts,
load/freeze timestamps, relevant environment versions, artifact hashes, the TechQA README/executable
count discrepancy, split diagnostics, and validation outcomes.

`phase01_integrity_report.json` stores check ID, expected/observed values, status, severity, and
details for persisted schema, uniqueness, coverage, filename/duplicate/component leakage, RAGTruth
source grouping, anomaly handling, and hashes. Any P0 failure makes the phase command fail.
